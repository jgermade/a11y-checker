# P1 — IBM Equal Access provider and cross-engine dedup

Plan: `ROADMAP/2026-11-26/post-mvp.md#p1--ibm-equal-access-provider`.

## 2026-11-26 — Investigation

`accessibility-checker-engine` 4.0.35 (Apache-2.0):

- `ace.js` defines a global `var ace` and has no module export. `ace-node.js` is the same
  engine with `module.exports`, and it requires no Node modules, so it can be bundled for
  the browser.
- API: `new Checker().check(nodeOrDocument, [guidelineId])` returns
  `{ results: Issue[] }`.
  - Guidelines: `WCAG_2_0`, `WCAG_2_1`, `WCAG_2_2` (A and AA), `IBM_Accessibility`
    (a superset with recommendations), `IBM_Accessibility_next` and `EXTENSIONS`.
- Each result has:
  - `ruleId`, `reasonId`, `message`, `snippet` and `path.dom` (XPath);
  - **`node`, the real DOM node**;
  - `value: [policy, confidence]`, where the policy is VIOLATION, RECOMMENDATION or
    INFORMATION and the confidence is PASS, FAIL, POTENTIAL or MANUAL.
- The engine itself walks into **same-origin iframes** (`/iframe[1]/html[1]/...`) and
  **shadow roots** (`#document-fragment[1]`). Cross-origin frames are unreachable.
- Rule metadata comes from `checker.engine.getRule(id)`:
  - `messages['en-US'].group` is the rule summary;
  - `help['en-US'][reason]` is a file name; the help URL is
    `https://able.ibm.com/rules/archives/latest/doc/en-US/<file>`;
  - `rulesets[]` holds `{ id: [guidelines], num: [WCAG SCs], level }`;
  - `act` is a string, a list of strings, or a list of `{ actId: {...} }` objects.
- 174 rules. A WCAG 2.2 check of a small fixture takes about 40 ms in Chromium.

## 2026-11-26 — Implementation

**core:**

- `getNodeTarget(node, top?)` builds a `NodeTarget` from a real DOM node, through shadow
  roots and same-origin frames. Selectors use a unique `#id` (CSS-escaped, ignoring
  duplicated ids) or an `nth-of-type` path anchored on the root or on the nearest
  unique-id ancestor.
- `resolveTarget(doc, target)` does the reverse. It returns `null` when a step cannot be
  resolved, including cross-origin frames and invalid selectors.
- **Dedup** (`dedupe.ts`), applied in `runCheck` when `config.dedupe` is on (the default):
  - Two issues are related if they come from different engines, have the same outcome,
    and share an ACT rule ID **or** a WCAG criterion. Nodes are matched by **element
    identity** in the page (`resolveTarget`), falling back to the formatted target.
  - The engine registered first keeps the issue. Matched nodes get
    `engines: [first, second]`, the highest impact, and both messages
    (`second: message`).
  - Unmatched nodes stay in the later issue, which is dropped when it is left with no
    nodes. Both issues list each other in `relatedRules`. The input is not mutated.
- New optional fields: `IssueNode.engines` and `Issue.relatedRules` (`RelatedRule`).
  They are additive, so existing consumers keep working.

**`@a11y-checker/engine-ibm`:**

- `createIbmEngine({ ace?, version? })` uses `ace-node.js`. ESM/CJS interop is handled:
  bundlers expose named exports, Node's ESM loader only `default`.
- The guideline is `WCAG_2_x` from `wcag.version`, or `IBM_Accessibility` with
  `bestPractices`.
- Classification:
  - VIOLATION + FAIL → violation, impact `serious`;
  - VIOLATION + POTENTIAL or MANUAL → incomplete, impact `moderate`;
  - RECOMMENDATION → impact `minor`, with **no WCAG criteria**, so it counts as a best
    practice;
  - PASS → pass;
  - INFORMATION is ignored.
- WCAG criteria come from `rule.rulesets[guideline].num`, keeping only real WCAG 2.x
  numbers. ACT IDs come from `rule.act` (all three shapes). Help URLs are built from
  `rule.help`.
- Targets are built from `result.node`. The include and exclude selectors are applied
  after the check, crossing shadow roots and frames (`scopeFilter`).
- The engine version is injected at build time (`__IBM_ENGINE_VERSION__` through tsdown
  `define` and Vitest `define`).
- IIFE `dist/engine-ibm.iife.js` (670 kB) with global `A11yCheckerIbm`, exported as
  `@a11y-checker/engine-ibm/iife`. The SDK's IIFE stays axe-only, and the SDK does not
  depend on engine-ibm.

**SDK:**

- The IIFE now also exports `createAxeEngine`. Without it, in-page code could not build
  a list of several engines.
- Re-exports `RelatedRule`, `getNodeTarget` and `resolveTarget`.
- SARIF adds `rule.properties.relatedRules` and `result.properties.engines`.
- HTML shows "Also reported by" and "(reported by axe, ibm)".

**Extension:**

- The `engines` setting (`lib/engines.ts`): axe-core is the default, IBM is optional,
  and the list can never be empty. The checkbox of the last enabled engine is disabled.
  The canonical order axe → ibm decides which engine keeps a merged issue.
- The background injects the SDK into every frame (axe-core needs it in each frame) and
  the IBM bundle **only into the top frame**, because IBM walks same-origin frames by
  itself.
- `runInPage` now returns errors as values. An exception inside `executeScript` turns
  into an empty result and loses its message: that hid the missing `createAxeEngine`
  export during development.
- Panel:
  - a "Show issues from" filter when several engines ran;
  - an "Also reported by" row;
  - "(reported by axe-core and IBM Equal Access)" on merged nodes;
  - the engine label in the Rule row.

**Verification:**

- 135 tests in total. New ones:
  - core: `dom` and `dedupe`, including identity matching with different selectors.
  - engine-ibm: unit tests for classification and mappings, and a browser test (page,
    shadow DOM, same-origin frame, scope filter, and **merging with axe**).
    - Real merge results: image-alt + img_alt_valid on `#no-alt` and in the shadow root;
      color-contrast + text_contrast_sufficient on `#low`.
    - The image inside the frame stays IBM-only, because axe-core was not loaded in that
      frame.
  - Reporters: related rules and engines in SARIF and HTML.
  - Extension e2e: both engines, a merged node credited to both, the engine filter, the
    last-engine guard, and **the panel's own check with both engines in light and dark
    mode**.
- `web-ext lint` gives 0 errors, and the IBM bundle adds no warnings.
- The store zips are about 380 kB. Rebuilding from the sources zip is still identical.

**Known limitations:**

- The IBM engine cannot reach cross-origin frames. axe-core covers them, so their issues
  come from axe only.
- Merging matches by **ACT rule or WCAG criterion** plus the same element. Two different
  problems on the same element under the same criterion (for example, 4.1.2) can be
  merged into one issue. Both rules stay visible through `relatedRules`, and
  `dedupe: false` turns merging off.
- IBM's impact is derived from policy and confidence, not reported by the engine.
