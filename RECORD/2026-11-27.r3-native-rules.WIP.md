# R3 — Native engine, second rule set (WIP)

Roadmap phase R3 in `ROADMAP/2026-11-26/next-phase.md`: about 12 more ACT rules for the
native engine, each shipped only when consistent with all its official test cases.

## 2026-11-27 — ARIA attribute rules (r3a)

New file `packages/engine-native/src/rules/aria-attributes.ts`, built on aria-query
5.3.2 (WAI-ARIA 1.2 data):

| Rule | ACT | Test cases |
|---|---|---|
| `aria-required-attr` | 4e8ab6 | 16 |
| `aria-allowed-attr` | 5c01ea | 17 |
| `aria-valid-attr-value` | 6a7281 | 21 |

Consistent with all 54 test cases in Chromium, Firefox and WebKit (258 test cases in
total now). In the regenerated ACT report, axe-core is only partial on 6a7281 and IBM
inconsistent.

Decisions and findings:

- **Global states and properties** are the props of the abstract `roletype` role.
- **5c01ea "language feature"** (ARIA in HTML): a small allowlist of attributes native
  elements support without a declaring role (`aria-checked` on native checkboxes and
  radios; `aria-required`/`aria-readonly` on form fields; `aria-disabled`,
  `aria-invalid`, `aria-errormessage` on form controls and fieldsets). The test cases
  do not exercise much of it; extend when needed.
- **6a7281:** `undefined` is valid for `true/false/undefined` types (aria-query's
  `allowundefined`) and for tristates. ID references only need to be a single token;
  the referenced element does not have to exist (rule exception).
- **4e8ab6:** aria-query still lists WAI-ARIA 1.1 implicit values that ARIA 1.2 removed
  (`aria-level` on heading, `aria-expanded` on combobox, `aria-checked` on checkbox and
  switch). Those are overridden, so they count as required. A focusable `separator` is
  a widget and then requires `aria-valuenow` (aria-query does not model this).
- Impact `critical` for the three, like axe-core's rules of the same names.

## 2026-11-27 — Heading, autocomplete and meta rules (r3b)

New files `src/rules/content.ts` and `src/rules/meta.ts`:

| Rule | ACT | Test cases | WCAG | Impact |
|---|---|---|---|---|
| `heading-name` | ffd0e9 | 15 | 1.3.1, 2.4.6 | moderate |
| `autocomplete-valid` | 73f2c2 | 30 | 1.3.5 | serious |
| `meta-viewport` | b4f0c3 | 16 | 1.4.4 | critical |
| `meta-refresh` | bc659a | 15 | 2.2.1 | critical |
| `meta-refresh-no-exception` | bisz58 | 13 | 2.2.4, 3.2.5 | minor |

Consistent with all 89 test cases in Chromium, Firefox and WebKit. The native engine
now has 20 rules and 347 test cases. In the regenerated report, axe-core is inconsistent
on bc659a and bisz58, and IBM does not report the meta and heading rules.

Decisions and findings:

- **73f2c2:** the "correct autocomplete field" is any field name of the HTML autofill
  table; the rule does not check that the field fits the control type. Contact types
  (home, work, mobile, fax, pager) are only valid before a contact field (tel*, email,
  impp). The "static" exception uses the roles that inherit from the abstract `widget`
  role in aria-query. "Disabled" includes an ancestor with `aria-disabled="true"`.
- **bc659a / bisz58:** `refreshTime()` follows the HTML shared declarative refresh steps
  (digits, optional `.`/digits, then the end or `;`, `,` or whitespace). The rules
  apply to the first meta refresh with a valid value.
- **b4f0c3:** numbers are read like the CSS Device Adaptation translation (a leading
  number); anything else for user-scalable or maximum-scale fails.
- **Harness:** meta refresh test cases reload or redirect the page, which destroyed the
  page while it was being checked. Only the first top-level navigation of each test
  case is now served; later ones (and top-level navigations to other hosts) get
  `204 No Content`, which browsers ignore. Aborting them was not enough: Chromium then
  shows an error page.
- Unit tests for the three parsers in `test/parsers.test.ts` (30 cases).
- Full local run: format, lint, typecheck, build and 322 tests passed (2 skipped).

## 2026-11-27 — Table and contrast rules (r3c)

| Rule | ACT | Test cases | WCAG | Impact |
|---|---|---|---|---|
| `td-headers-attr` | a25f45 | 19 | 1.3.1 | serious |
| `color-contrast` | afw4f7 | 34 | 1.4.3 | serious |
| `color-contrast-enhanced` | 09o5cg (AAA) | 35 | 1.4.6 | serious |

Consistent with all 88 test cases in Chromium, Firefox and WebKit. The native engine
now has 23 rules and 435 test cases. In the regenerated report, axe-core is partial on
both contrast rules (images and shadows give "needs review") and IBM is inconsistent
on afw4f7.

**Contrast design** (`src/color.ts`, `src/rules/contrast.ts`):

- Targets are elements with visible text nodes as flat-tree children (shadow root text
  belongs to the host; slotted text to the slot).
- Background: walk up the flat tree stacking background colors and gradient color
  stops, with their alpha, until an opaque layer; then composite over the white
  canvas. Opacity multiplies the text alpha and the layers collected so far. Up to 16
  candidate backgrounds.
- A blurred text shadow (blur > 0) replaces the backgrounds right behind the glyphs:
  Passed Example 4 (white glow) passes and Failed Example 11 (grey glow on white)
  fails, which taking the maximum over shadow and background together would not.
- Highest possible contrast over the candidates, as in the ACT rules. Large text:
  18pt, or 14pt bold, with a 0.01pt tolerance (Firefox and WebKit compute 14pt as
  18.6667px, which is 13.9999pt).
- Not applicable: text with the same color as everything behind it (not visible), and
  text inside a disabled widget or group, or in a label of a disabled widget (labels
  and aria-labelledby). Passes: text without letters, and a single letter (a symbol).
- **Limitation: background images are not analyzed**; the background color under them
  is used. That gives the expected outcomes for the two image test cases (the black
  background color decides both), but real pages with images can be misjudged. Same
  for text positioned over unrelated content. Documented in the README.
- Colors in other notations (`oklch()` and so on) are validated with `CSS.supports`
  and read back from a 1×1 canvas. The first version used `fillStyle` round trips,
  which keep `oklch()` in modern browsers and left WebKit returning the previous
  color for invalid values; caught by the new `color.browser.test.ts`.

Unit tests: `test/color.test.ts` (parsing, compositing, ratios) and
`test/color.browser.test.ts` (canvas path in the three browsers).

Full local run: format, lint, typecheck, build and 332 tests passed (2 skipped).

**R3 scope status:** every candidate rule in the roadmap is implemented (11 rules:
4e8ab6, 5c01ea, 6a7281, ffd0e9, 73f2c2, b4f0c3, bc659a, bisz58, a25f45, afw4f7,
09o5cg). Close this record once CI is green on GitHub.
