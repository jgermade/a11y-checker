# R3 — Native engine, second rule set (WIP)

Roadmap phase R3 in `ROADMAP/2026-11-26/next-phase.md`: about 12 more ACT rules for the
native engine, each shipped only when consistent with all its official test cases.

## 2026-11-27 — ARIA attribute rules (r3a)

New file `packages/engine-native/src/rules/aria-attributes.ts`, built on aria-query
5.3.2 (WAI-ARIA 1.2 data):

| Rule | ACT | Test cases |
|---|---|---|
| `aria-required-attr` | 4e8ab6 | 16 |
| `aria-allowed-attr` | 5c01ea | 17 |
| `aria-valid-attr-value` | 6a7281 | 21 |

Consistent with all 54 test cases in Chromium, Firefox and WebKit (258 test cases in
total now). In the regenerated ACT report, axe-core is only partial on 6a7281 and IBM
inconsistent.

Decisions and findings:

- **Global states and properties** are the props of the abstract `roletype` role.
- **5c01ea "language feature"** (ARIA in HTML): a small allowlist of attributes native
  elements support without a declaring role (`aria-checked` on native checkboxes and
  radios; `aria-required`/`aria-readonly` on form fields; `aria-disabled`,
  `aria-invalid`, `aria-errormessage` on form controls and fieldsets). The test cases
  do not exercise much of it; extend when needed.
- **6a7281:** `undefined` is valid for `true/false/undefined` types (aria-query's
  `allowundefined`) and for tristates. ID references only need to be a single token;
  the referenced element does not have to exist (rule exception).
- **4e8ab6:** aria-query still lists WAI-ARIA 1.1 implicit values that ARIA 1.2 removed
  (`aria-level` on heading, `aria-expanded` on combobox, `aria-checked` on checkbox and
  switch). Those are overridden, so they count as required. A focusable `separator` is
  a widget and then requires `aria-valuenow` (aria-query does not model this).
- Impact `critical` for the three, like axe-core's rules of the same names.
