# MVP planning

## 2026-11-26 — Initial planning

**Context:** The goal is an accessibility validator. The MVP is the engine, offered as an
SDK and as a Chrome extension. E2E testing comes later.

**Decisions:**

- **Wrap axe-core first** instead of writing our own engine. We will add IBM Equal Access
  later as a second provider, and then a 100% in-house engine.
- The core defines its own result model, config and `EngineProvider` interface, so engines
  can be swapped or combined without changes to the public API.
- The engine does not depend on its environment (DOM only), and ships an injectable IIFE
  bundle that the extension and future E2E adapters reuse.
- Every issue maps to WCAG success criteria and W3C ACT rule IDs. This makes cross-engine
  dedup and ACT conformance testing possible.
- Tooling: pnpm monorepo, TypeScript, Vitest + Playwright, Changesets, WXT for the extension.
- Reporters: JSON, SARIF 2.1, HTML.

**Projects evaluated** (as references or dependencies): axe-core, Siteimprove Alfa,
IBM Equal Access, HTML_CodeSniffer, QualWeb, W3C ACT Rules, aria-query,
dom-accessibility-api, Accessibility Insights for Web, WXT/Plasmo/CRXJS, Playwright,
Cypress, pa11y, jest-axe, Guidepup.

**Output:** `ROADMAP/2026-11-26/` (overview, MVP, post-MVP).

**Open questions:**

- npm scope and package names (`@a11y-checker/*` is a placeholder).
- Should the extension support Firefox early, since WXT makes it cheap?
- Assumption: one developer. The schedule must be revisited if the team size differs.
