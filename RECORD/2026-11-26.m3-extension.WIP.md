# M3 — Browser extension (Chrome + Firefox)

Plan: `ROADMAP/2026-11-26/mvp.md#m3--browser-extension-chrome--firefox`.

## 2026-11-26 — Implementation

**Stack:** WXT 0.21 (Vite 8), Manifest V3 for both browsers, and Preact 11 for the panel
UI. WXT auto-imports are disabled (`imports: false`) in favor of explicit imports.

**Structure** (`packages/extension`, private package):

- `entrypoints/devtools`: registers the **a11y-checker** DevTools panel. It is not named
  "Accessibility" because Chrome already has an Accessibility pane.
- `entrypoints/devtools-panel`: the Preact UI.
  - Toolbar with settings (WCAG version and level, best practices, needs review,
    group by) and export (JSON, SARIF, HTML).
  - Live status region, and notices for stale results, unchecked frames and engine errors.
  - Summary, then sections for violations and needs review, with groups and expandable
    issues.
  - Each node has Highlight and Inspect buttons.
- `entrypoints/background.ts`: accepts messages only from the extension's own pages, by
  checking that `sender.url` is an extension URL. A first version rejected senders with
  `sender.tab`, which also rejected the panel when it is opened as a tab.
- `entrypoints/popup`: tells the user to open DevTools and use the panel.
- `lib/`: pure, tested logic. `settings`, `group`, `export`, `locate` (self-contained
  so it can be serialized), `check-tab` and `messages`.
- `host.ts` abstracts DevTools. Opened as `devtools-panel.html?tabId=<id>`, the panel
  works without DevTools (Inspect is hidden). The e2e tests use this mode.

**Check flow** (`lib/check-tab.ts`), all through `scripting.executeScript` in the
isolated world:

1. Remove any highlight.
2. Probe every frame for loaded engine, origin and number of child frames.
3. Inject `a11y-checker.iife.js` into the frames that do not have it.
4. `allowFrameOrigins` with the tab's own origins (not `ALL_ORIGINS`).
5. Run the check in frame 0.
6. In a `finally` block, restore `SAME_ORIGIN` in every frame.

The IIFE comes from `@a11y-checker/sdk/iife` through the WXT `build:publicAssets` hook,
and the `prepare:publicPaths` hook types its path.

**Findings:**

- **Sandboxed iframes:** Chrome injects the content script, but the frame's origin is
  opaque (`null`). axe-core cannot address it and skips it silently. The extension now
  counts such frames as unchecked and the panel shows a notice.
- axe target selectors for iframes are `#id`, not `iframe#id`.
- Extension pages block injected `<script>` tags (CSP). The self-check test runs the
  engine with `page.evaluate(source)`, which bypasses the CSP.
- Playwright: extensions need `channel: 'chromium'` (full build, new headless), not the
  default headless shell.

**Permissions:** `scripting`, `storage` and host access to `<all_urls>`.
**Deviation from the plan:** the plan said `activeTab`. `activeTab` is not granted by
opening DevTools, and it does not cover cross-origin iframes, so host access is required.
The justification is written in `packages/extension/STORE.md`.

**Tests (101 in total):**

- Unit: settings, grouping and export.
- Browser: `locateNode` through shadow DOM and frames, and `inspectExpression` evaluated
  like DevTools `eval()`.
- **e2e** (new Vitest project `e2e`, with a global setup that runs `pnpm build` unless
  `A11Y_CHECKER_PREBUILT=1`; CI sets it after its build step): the built Chrome extension
  in Chromium.
  - Shadow DOM and same-origin, cross-origin and sandboxed iframes; the notice for the
    sandboxed frame.
  - Highlight (a cross-origin node highlights its iframe) and its removal before the next
    check.
  - SARIF download, settings persistence, and the stale-results notice.
  - **The panel checks itself with no violations in light and dark mode.**
- The SDK's IIFE test moved to the e2e project (`iife.e2e.test.ts`) and no longer
  rebuilds by itself. This avoids two tests rebuilding `dist/` at the same time.

**Firefox:**

- `web-ext lint` (added as a devDependency, script `lint:firefox`) reports 0 errors.
- The warnings are axe-core's `Function` and `innerHTML` and Preact's `innerHTML`.
- One warning about Firefox for Android is not relevant: Android has no DevTools.
- `strict_min_version` is 140 (needed for `data_collection_permissions`, which is set to
  `none`).
- **Not run in a real Firefox** here (no Firefox in this environment). This is a manual
  check before the AMO submission.

**Packaging:**

- `pnpm --filter @a11y-checker/extension zip` writes `a11y-checker-<v>-chrome.zip`,
  `-firefox.zip` and `-sources.zip`.
- The sources archive is the whole monorepo, without generated folders.
- **Verified:** rebuilding from the sources zip produces a Firefox build identical to the
  original.
- CI uploads the zips as the `browser-extension` artifact.
- The changeset now bumps the extension to 0.1.0 (`privatePackages.version: true`).

**Pending to close M3:**

## 2026-11-26 — CI fix

The first CI run of M3 failed at lint. `@a11y-checker/sdk/reporters` did not resolve for
typed lint before a build, because the `@a11y-checker/*` path maps to
`packages/sdk/reporters/src`. Locally it resolved through the built `dist/`. An explicit
path for the subpath was added to `tsconfig.base.json`. Verified with every `dist/` and
`.output/` removed.
