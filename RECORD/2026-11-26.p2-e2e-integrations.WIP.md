# P2 — E2E integrations

Plan: `ROADMAP/2026-11-26/post-mvp.md#p2--e2e-integrations`.

## 2026-11-26 — Start

Order of work:

1. SDK: `check({ element })` to check a single element. This was deferred from M2 and
   every adapter needs it.
2. `@a11y-checker/matchers`: `toBeAccessible()` for Vitest and Jest, in a DOM.
3. `@a11y-checker/playwright`: `checkA11y(page | locator)` and the `toBeAccessible()`
   matcher.
4. `@a11y-checker/cli`: scan URLs, failure threshold, text, JSON, SARIF and HTML output.
5. `@a11y-checker/cypress`: the `cy.checkA11y()` command.

Design decisions:

- **Element scope without changing the config model.** The config stays
  JSON-serializable. `check({ element })` marks the element with a temporary
  `data-a11y-checker-scope` attribute, uses it as the only `include` selector, and removes
  it from the element and from the HTML snippets afterwards.
- **No Playwright types in public `.d.ts` files.** Structural `PageLike`, `FrameLike` and
  `LocatorLike` interfaces avoid a hard peer dependency, whose types pnpm users might not
  be able to resolve.
- The engine bundles are injected with `frame.evaluate(source)`, not `addScriptTag`, so
  page CSPs cannot block them.

## 2026-11-26 — Implementation

**SDK:**

- `check({ element })`. The element must be in its document's light DOM.
  - After the check, the temporary `data-a11y-checker-scope` attribute is removed from the
    HTML snippets, and `config.include` shows the element's own selector instead.
- Reporters: `toText()`, `formatIssues()` and `violationsAtLeast(result, failOn)`. A
  violation without an impact always counts.
- The IIFE also exports `toText`.
- **Bug fixed:** `version.ts` imported `package.json` without
  `with { type: 'json' }`. This broke any Node ESM loader that runs the TypeScript
  sources, such as Playwright's runner with tsconfig paths. The attribute is now there.

**`@a11y-checker/matchers`:**

- `toBeAccessible()` (async) accepts an Element or a Document.
- `toHaveNoViolations()` works on `CheckResult` objects.
- `failOn` defaults to `minor`. The matchers check only violations by default.
- Setup entries: `/vitest` augments Vitest 5's `Matchers<R, T>` (peer `vitest >= 5`), and
  `/jest` uses `setupFilesAfterEnv` and the `jest.Matchers` augmentation.

**`@a11y-checker/playwright`:**

- `checkA11y(page | locator, { engines, ...config })`.
  - Loads the SDK IIFE into every frame through `frame.evaluate(source)`, so the page CSP
    is bypassed (tested with `script-src 'none'`).
  - The IBM IIFE is loaded into the main frame, or into every frame for locator checks.
  - Opens cross-origin access between the page's origins during the check, then closes
    it.
  - Locator checks run in the locator's own frame. A locator inside a cross-origin frame
    was tested.
  - Returns `frames: { total, checked }`.
- `a11yMatchers.toBeAccessible`:
  - attaches `accessibility-report.html` and `.json` through `test.info()`, using a
    dynamic import of `@playwright/test` (an optional peer);
  - applies `failOn`;
  - mentions unchecked frames in its message.
- Structural `FrameLike`, `PageLike` and `LocatorLike` types. The callback parameters are
  `any`, because Playwright's `Unboxed<Arg>` cannot be matched otherwise. This was found
  by type-checking the tests against the real `Locator`.
- tsdown `platform: node` writes `.mjs` by default. `fixedExtension: false` keeps `.js`,
  which matches `exports`.

**`@a11y-checker/cli`** (`a11y-checker` binary, Node 22+, Playwright for the browsers):

- Options: `--wcag`, `--level`, `--best-practices`, `--engines`, `--include`,
  `--exclude`, `--rules`, `--disable-rules`, `--fail-on` (including `none`), `--format`
  (text, json, sarif, html), `--output`, `--incomplete`, `--urls <file>`, `--browser`,
  `--timeout` and `--wait-for`.
- Exit codes: 0 when no violation reaches the threshold, 1 when one does, 2 on errors
  (usage, navigation or engine). The other URLs are still reported.
- With several URLs: JSON is an array, SARIF has one log with one run per URL, and HTML
  needs `--output <dir>` and writes one file per URL.
- Bare host names get `https://`. Only http(s) and file URLs are accepted.

**`@a11y-checker/cypress`:**

- `cy.checkA11y(options?)`, which can take a subject (`cy.get(...).checkA11y()`).
  - `failOn` accepts any impact or `'none'`.
  - Each violation goes to the command log, with `$el` and `consoleProps`.
  - Yields a plain `CheckResult`.
- **Finding:** `axe.source` comes from calling `toString()` on a function. When Cypress'
  webpack bundles axe-core, that code is rewritten with webpack's module wrappers, and
  evaluating it in the application window fails with "exports is not defined". The fix
  is a small tsdown plugin that inlines `@a11y-checker/sdk/iife` as a **string**
  (`?raw` import forced into the bundle with `deps.alwaysBundle`). The bundle is
  evaluated in the application window and its same-origin frames, and the check runs
  there.

**Tests:** 179 in total, all passing from a clean state.

- New e2e tests:
  - Playwright library: page, locator, cross-origin frame, a locator inside a
    cross-origin frame, CSP, IBM merge, matcher.
  - A **real `@playwright/test` project**: `expect.extend`, attachments, an expected
    failure with formatted violations. It has its own tsconfig so it uses the built
    packages.
  - The CLI against a local HTTP server: exit codes, `--fail-on`, JSON, SARIF, HTML,
    `--urls`, both engines, `--wait-for`, unreachable URLs, help and version.
  - A **real Cypress 16 run** (Electron with Xvfb), 5 specs. The test is skipped when
    the binary is missing, unless `A11Y_CHECKER_REQUIRE_CYPRESS=1`. CI now runs
    `cypress install` and sets that variable.
- Packaging: every package was packed. Installing the CLI from the tarballs with npm and
  checking a page with both engines works, and the results are merged.

**Known limitations:**

- Cypress cannot reach cross-origin iframes, and only axe-core runs there.
- The matchers in simulated DOMs report layout-dependent rules as incomplete, which never
  fail.
- The CLI's `file:` URLs and `--browser firefox` and `webkit` are not tested here (only
  Chromium is installed).

## 2026-11-26 — CI fix

The first CI run failed at the format check. The P2 commit had accidentally included
Playwright run artifacts (`packages/playwright/test-results/`), written by the
`@playwright/test` integration test. The fix:

- remove them from the repository;
- add `test-results/`, `playwright-report/` and Cypress' screenshots, videos and
  downloads folders to `.gitignore` (and the first two to `.prettierignore`);
- point the test project's `outputDir` to `node_modules/.cache`, so runs no longer write
  into the source tree.
