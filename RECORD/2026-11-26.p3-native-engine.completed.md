# P3 — In-house engine

Plan: `ROADMAP/2026-11-26/post-mvp.md#p3--in-house-engine`.

## 2026-11-26 — Start

Scope of this first iteration:

- `@a11y-checker/engine-native`, with:
  - a rule authoring API modeled on W3C ACT rules (applicability, then expectation per
    element, giving passed, failed or cantTell);
  - an accessibility layer: accessible name (`dom-accessibility-api`), roles and ARIA
    metadata (`aria-query`), visibility, and a composed tree walk through open shadow
    roots and same-origin iframes.
- About 12 rules, each validated against the **official W3C ACT test cases**, which are
  stored in the repository under the W3C license.
- An EARL implementation report and a **benchmark** that runs axe-core and IBM Equal
  Access on the same test cases.
- Integration as a third engine in the SDK consumers: Playwright, the CLI and the
  extension.

Network check: `www.w3.org` (ACT test cases JSON, 1.3 MB) and `www.iana.org` (language
subtag registry) are reachable from the environment.

## 2026-11-26 — Implementation

**`@a11y-checker/engine-native`** (engine id `native`):

- **Rule API** (`rule.ts`): `defineRule({ id, actRuleIds, wcag, impact, description,
  help, helpUrl, applicability(ctx), expectation(target, ctx) })`, where the
  expectation returns passed, failed or cantTell with a message.
  - `runRules()` returns raw ACT results per target. A rule that throws reports cantTell
    for its targets and does not stop the others.
  - `toIssues()` maps failed → violation, cantTell → incomplete and passed → pass. A rule
    with no targets gives an inapplicable issue.
  - `createNativeEngine({ rules })` applies include/exclude with core's new
    `createScopeFilter()`, which the IBM engine now uses too.
- **Accessibility layer** (`a11y.ts`, exported as the `a11y` namespace):
  - `composedElements()` walks open shadow roots and same-origin iframes.
  - `isProgrammaticallyHidden()` uses `dom-accessibility-api`'s `isInaccessible`.
    `<area>` elements are judged through the image that uses their map.
  - `semanticRole()` uses `getRole` plus the **presentational conflict resolution for
    focusable elements**, which the library lacks. The implicit role comes from a
    role-less clone, and disabled elements are not focusable.
  - `accessibleName()` uses `computeAccessibleName` with two fallbacks: the
    `placeholder` of text fields, and name from content (including image `title`) for
    roles the library does not handle, such as the DPUB-ARIA link roles.
  - Visibility: `checkVisibility`, boxes, clip patterns, off-screen positions and
    transparent text.
  - `isInSequentialFocusNavigation()`: only native `:disabled` and `inert` remove focus;
    `aria-disabled` does not.
- **12 rules**:
  - 23a2a8 image name, 97a4e1 button name, c487ae link name, e086e5 form field name (date
    and time inputs count as textbox), cae760 iframe name;
  - b5c3f8 page lang, bf051a page lang valid, de46e4 element lang valid (only text that
    is visible or exposed counts), 2779a5 page title;
  - 6cfa84 aria-hidden focus (with a **focus probe for sentinels** that hand focus
    elsewhere; focus is restored), 674b10 valid role (`aria-query`, non-abstract);
  - 2ee8b8 label in name: the ACT tokenizer and "visible inner text". Heuristics: a
    single letter is a symbol (a single digit is text), and text in known icon fonts is
    an icon.
- **Language tags:** 8275 primary subtags extracted from the IANA registry
  (`scripts/fetch-language-subtags.mjs`, registry date 2026-11-18), plus the private-use
  range `qaa..qtz`.

**ACT conformance:**

- `scripts/fetch-act-testcases.mjs` stores the 204 test cases of the 12 rules and 7
  shared assets under `test/act/`. It is polite to w3.org: one request at a time, retry
  with backoff on 429 (which did happen), and resume.
- The harness (`test/act/harness.ts`) opens each test case as a **top-level page** at its
  w3.org URL, served from the local files as UTF-8, with every other request blocked.
- **Result: 204 out of 204 test cases consistent.** The first run gave 190. The fixes,
  all described above: text inheriting language, conflict resolution for focusable and
  disabled elements, placeholder, area, name from content, aria-disabled, focus
  sentinels, date inputs, iframes marked decorative, the symbol and icon-font
  heuristics, and a harness bug (the HTML was served without a charset, so "…" was read
  as Latin-1).
- `pnpm act:report` (a Vitest e2e test gated by `A11Y_ACT_REPORT=1`, about 36 s) writes
  `act-report.earl.json` (EARL JSON-LD) and `ACT-REPORT.md` (the benchmark).
- **Benchmark** in this environment (default rules; network blocked, so web fonts do not
  load):
  - native: consistent on all 12 rules.
  - axe-core 4.14.1: consistent on 9, partial on 6cfa84, inconsistent on b5c3f8 and
    2ee8b8.
    - b5c3f8: the XML example is served as `application/xml`.
    - 2ee8b8: the Material Icons example depends on the web font loading.
  - IBM: consistent on 4, partial on 1, inconsistent on 7.
  - These are documented caveats, not claims about the tools' official reports.
- **Correction before publishing:** I almost wrote in the README that axe-core's 2ee8b8
  rule is experimental and disabled. I checked: in axe-core 4.14,
  `label-content-name-mismatch` is enabled and not experimental. The claim was removed.

**Integration:**

- Playwright (`engines: ['native']`, with engine-native as an optional peer), the CLI
  (`--engines native`) and the extension (checkbox "a11y-checker (ACT rules)", injected
  into the top frame).
- The extension lists merged engines with `Intl.ListFormat`.
- The extension's sources zip now excludes `packages/*/test/**`, so the ACT fixtures stay
  out (242 kB). Rebuilding from it is still identical.

**Tests:** 210 in total, all passing from a clean state, plus the ACT report test, which
is skipped by default. New ones:

- unit: language tags, tokenizer and label in name;
- browser: the engine through `runCheck`, its metadata, passes and inapplicable rules,
  the merge with axe, custom rules and a rule that throws, rule ID uniqueness;
- e2e: ACT conformance;
- Playwright, CLI and extension tests with the native engine.

**Next steps (not done):**

- ARIA attribute rules (5c01ea, 6a7281, 4e8ab6), contrast, headings and landmarks.
- Submitting the EARL report to the ACT Rules Community.
- Check whether results stay the same in Firefox and WebKit.
